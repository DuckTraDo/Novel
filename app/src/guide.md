# 📖 Sodarie Novel · 操作指南

欢迎！这是一台「你掌舵、模型划桨」的长篇小说写作机器。

它的核心想法很简单：**你只用一句话告诉它这章要发生什么，它一次性把整章写出来；而那些容易写着写着就崩的事——人物前后矛盾、伏笔忘了收、第 3 章的设定到第 30 章变了样——交给「长期记忆」帮你盯着。**

读完这篇你就全会了，大概五分钟。☕

---

## 🌀 一分钟看懂整个流程

```
准备记忆库 → 写一句章节 idea → 生成整章 → 你审阅/改 → 一致性检查 → 更新记忆 → 下一章
```

每一章都走这个循环。前面写过的人物、事件、伏笔会被「记忆」记下来，喂给后面的章节，所以越往后越连贯，而不是越写越乱。

> 一句话心法：**idea 决定这章写什么，记忆库决定这章和前文对不对得上。**

---

## 🍱 开始之前：先把「记忆库」喂饱

记忆库就是这本书的「设定集 + 账本」。模型写每一章前都会先翻一遍。喂得越用心，写出来越像「你的书」，而不是一篇通用网文。

到左侧 **🧠 记忆库** 标签页编辑。下面逐个讲怎么写。**新书至少先填前三个**（故事圣经、角色档案、全书大纲），其余可以边写边补。

### 1. 故事圣经 `story_bible.yaml` —— 这本书的宪法

写世界观、主题、硬规则。模型违反这里的设定，一致性检查会揪出来。

```yaml
world_rules:        # 世界观规则（这个世界什么能发生、什么不能）
  - 这是近未来的中国南方县城，没有超自然力量
  - 死人不能复活，受伤需要时间恢复
writing_rules:      # 写作规则（你希望的笔法）
  - 多用动作和细节暗示情绪，少写"他很伤心"这类直白句
  - 对话要短，符合人物身份
forbidden_patterns: # 禁止出现的偷懒写法
  - 不要用"突然""忽然"开头
  - 不要"时光飞逝""不知不觉"这类一笔带过
```

> 💡 不知道写什么？先把「这本书绝对不能出现的东西」列出来，往往比列优点更有用。

### 2. 角色档案 `characters.yaml` —— 谁是谁，他知道什么

这是最重要的一个文件。字段含义：

| 字段 | 意思 | 为什么重要 |
|---|---|---|
| `name` | 角色名 | 记忆更新靠名字找人，**务必前后一致** |
| `current_status` | 当前状态/处境 | 模型据此知道他现在在哪、在干嘛 |
| `knows` | 他**已经知道**的信息 | 防止角色"知道了他不该知道的事" |
| `secrets` | 他藏着的秘密 | 防止过早揭秘 |
| `relationships` | 和别人的关系 | 让互动合理 |
| `constraints` | 限制（不能做/不会做的事） | 守住人设 |

```yaml
characters:
  - name: 林川
    current_status: 刚回到故乡，借住在老宅
    knows:
      - 父亲三年前去世
    secrets:
      - 其实当年是他先离的家
    relationships:
      - 与堂妹林晚关系疏远
    constraints:
      - 不擅长说谎，一紧张就回避眼神
```

> ⚠️ `knows` 和 `secrets` 是「防剧透」的关键。比如反派的真实身份只写进某人的 `secrets`，模型就不会让其他角色提前点破。

### 3. 全书大纲 `book_outline.yaml` —— 大方向

写全书的走向、分卷、关键节点。不用很细，给模型一个"地图"即可，避免它把第 5 章就该出现的高潮提前写了。

### 4. 伏笔 `foreshadowing.yaml` —— 埋了别忘了挖

分 `active`（埋下了、还没回收）和 `resolved`（已回收）。多数时候你不用手动写——跑「更新记忆」时模型会帮你登记。手动加也行：

```yaml
active:
  - id: fs001
    description: 老宅阁楼上锁的木箱
    planned_resolution: 第二卷揭示里面是母亲的日记
resolved: []
```

### 5. 风格库 `style_bank.jsonl` —— 给模型"抄"你的笔法

每行一条 JSON，放你满意的片段（你自己写的、或喜欢的范文）。模型会模仿这种调性。

```json
{"id": "style01", "text": "雨砸在铁皮棚上，像有人在头顶不停数着硬币。"}
```

> 💡 这里就是「文风」的来源。放 3~5 段就够了，贵精不贵多。

### 6. 自动维护的文件（手别痒）🤚

`章节摘要 / 事件流水 / 时间线 / 关系图` 这几个，**一般不用手动编**——它们是你每章跑「更新记忆」时自动生成的账本。除非要修个别错误，否则交给程序就好。

## ✍️ 章节工作台：每个按钮到底干嘛

到左侧 **✍️ 章节工作台**。从上到下：

### 选择章节 / 新建章节 ID / 自动编号
- **选择章节**：下拉选已有的章节来查看或重写。
- **新建章节 ID**：写新章节时，在这里填编号（如 `ch001`）。点 **自动编号** 会按现有章节自动 +1，省得自己数。

### 本章 idea —— 一句话方向（最高优先级）
告诉模型这章发生什么。**它的优先级最高**——哪怕和记忆库冲突，也以 idea 为准（潜在冲突只会在报告里提醒你，不会硬塞进正文）。

写法示例：
> 第一章：主角回到故乡，发现父亲留下的一封信，决定调查多年前的旧事。

不用写得像大纲，一两句点明"谁、在哪、做了什么、转折是什么"就够。给得越具体，跑偏越少。

### 目标字数
这章大概多少中文字，默认 4000。这是**目标值不是硬上限**，实际会上下浮动。

### ☑ 使用长期记忆 —— 什么时候勾，什么时候不勾
- **勾上（默认，推荐）**：把记忆库（人物、伏笔、前情摘要等）一起喂给模型 → 写出来和前文连贯。**正常写连载就一直勾着。**
- **不勾**：只看这一句 idea 写，完全无视前文设定。适合：
  - 写**开篇第一章**、还没攒下任何记忆时；
  - 写**番外 / 回忆 / 独立短章**，不想被主线设定干扰；
  - 单纯想让模型"放飞"试个写法。

### ☑ 覆盖已有正文
这章已经有正文了，想**重新生成**就勾上；否则程序会拦住你、防止误删。第一次写新章可勾可不勾。

### 生成 / 重新生成
点下去，模型开始写整章。期间按钮转圈，**请耐心等**——本地大模型写 4000 字通常要几十秒到几分钟。写完正文会自动出现在下面，同时生成一份「生成报告」。

### 正文（可编辑）+ 保存正文
生成的正文直接在框里，**你可以随手改**（改错别字、调句子、删段落）。改完点 **保存正文**。觉得整体不行就回上面重新生成。

### 一致性检查
让模型当编辑，拿这章正文去对照人物档案、世界观、伏笔、时间线，挑毛病（信息超前、设定漂移、重复事件、AI 腔等），结果写进「一致性报告」，到 **📋 报告** 页看。
> 它只给**建议**，不会改你正文。改不改你说了算。

### 更新记忆 —— 这一步别跳过！
这章定稿后点它。模型会从正文里**抽取**：本章摘要、发生的事件、人物状态变化、新伏笔、关系变化，写回记忆库。
> 这是"越写越连贯"的关键。**跳过它，后面的章节就不知道这章发生了什么。**
>
> 推荐顺序：**生成 → （改）→ 一致性检查 → 满意后再更新记忆**。别还没定稿就更新，否则记忆里记的是会被你改掉的版本。

> 🔑 **划重点：记忆的唯一入口就是这个按钮。**
> **生成、重新生成、保存正文，都不会写记忆。** 所以你可以放心地反复重新生成——
> 比如第一遍写成"大妈打了主角"，重新生成变"大妈给主角炒饭"，
> 只要你**没点过「更新记忆」**，那个被覆盖掉的版本就从未进过记忆，
> **不需要去清理、也不用勾连带记忆**。等满意了再点「更新记忆」，进账的就只有最终版。

### ☑ 连带记忆 + 重置本章 —— 看清楚再点 🧨
**重置本章** = 删掉这章的正文和它的报告。

旁边的 **☑ 连带记忆** 决定要不要**连这章在账本里的痕迹一起清掉**：
- **不勾**：只删正文和报告，保留记忆库里的记录。适合——**只想把正文推倒重写，但之前抽取的记忆还想留着**；或者你**还没跑过「更新记忆」**（那记忆里本来就没这章，勾不勾都一样）。
- **勾上**：除了正文报告，再从 **章节摘要 / 事件流水 / 时间线** 里删掉属于这章的记录。适合——**这章彻底作废、要从零重来**，不想让旧痕迹污染后文。

> ⚠️ 重要说明（避免误会）：「连带记忆」只清理 **摘要 / 事件 / 时间线** 这三本账。它**不会**自动回滚你在「更新记忆」时对**角色状态、伏笔、关系图**做过的改动——那些目前需要你到 🧠 记忆库 手动核对修正。所以：**作废一章前最好心里有数，它改过哪些人设。**
>
> 重置不可撤销，点之前会让你确认一次。

## 📋 报告页

**📋 报告** 页按章节看三份报告：
- **生成报告**：这章用了什么 idea、字数、模型信息、原始输出。
- **一致性报告**：编辑挑出的连贯性问题和建议。
- **记忆更新报告**：这章往记忆库写了哪些东西、有哪些连续性风险提示。

## 🎯 推荐节奏（照着做就顺）

1. 新书：先填 **故事圣经 + 角色档案 + 全书大纲**，放几段 **风格库**。
2. 到 **设置** 填好 **LLM Base URL**（务必带 `http://`）和模型名，保存。
3. 工作台：新建 `ch001` → 写一句 idea → **生成**。
4. 读一遍，随手改，**保存正文**。
5. **一致性检查**，看报告，按建议再改。
6. 满意了，**更新记忆**。
7. 新建 `ch002`，重复 3~6。就这样一路写下去。✨

## 🆘 常见问题 FAQ

**Q：点生成报错 `builder error` / `无法连接模型服务`？**
A：八成是 **LLM Base URL 没带协议头**。改成 `http://127.0.0.1:18180/v1` 这种完整地址（端口换成你自己的）。还连不上，就是你的本地模型服务没启动。

**Q：报 `HTTP 404`？**
A：地址路径不对。多数本地服务接口在 `/v1` 下；如果你的服务在根路径，就把结尾的 `/v1` 去掉。

**Q：更新记忆时 `JSON 解析失败`？**
A：模型这次没按规定格式吐 JSON。重试一次通常就好；老犯，可换个更听话的模型，或把它生成的内容核对一下。失败的原始输出会存到报告目录，方便排查。

**Q：生成的字数总是不够？**
A：本地模型的单次输出长度有上限。可到 **设置 / `config.yaml`** 调 `max_output_tokens`，或把长章拆成两章分别生成。

**Q：我的稿子存在哪？**
A：在 **项目目录**（设置页底部能看到完整路径）下的 `chapters/`，记忆在 `memory/`，报告在 `outputs/reports/`。想换地方，在设置里改 **项目目录**。
